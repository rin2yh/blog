## 概要

『基礎から学ぶTinyGo組み込み開発』を読んでいたところ、ビルドプロセスの説明で「SSA」という言葉が出てきました。
そもそもSSAという言葉自体を知らなかったので、いったん本を止めて調べてみました。

この記事は、そのとき調べた内容を、自分が理解できた範囲でメモしたものです。ビルドプロセスの細かい流れには踏み込みません。

## SSAとは（ざっくり）

SSAは、コンパイラが内部で使う「中間表現」の一種らしいです。

コンパイラはソースコードからいきなり機械語を作るわけではなく、間に扱いやすい形をはさみます。その中間の形を **IR（Intermediate Representation / 中間表現）** と呼ぶそうです。SSAはそのIRのひとつ、という位置づけでした。

SSAのルールはシンプルで、**変数への代入は一度きりにする**、というものです。
たとえば、普通のコードはこう書けます。

```go
x := 1
x = x + 2
y := x * 3
```

`x` に2回代入していますね。これをSSAでは、代入のたびに新しい名前を振って、こう表すそうです。

```
x1 = 1
x2 = x1 + 2
y1 = x2 * 3
```

`x1`、`x2` と番号を振って、「一度しか代入しない」形にする。今回わかったのは、ここまでです。

## なぜそんな形にするのか（自分なりの仮説）

「なんでわざわざ名前を振り直すんだろう？」と思ったので、自分なりに仮説を立ててみました。

私の予想は、**こうしておくと「その値がどこで作られたのか」がはっきりするから**、というものです。
`x2` と書いてあれば、それを作ったのは `x2 = x1 + 2` の1箇所だけだと一目でわかります。
普通に `x` を使い回していると「今の `x` はどの代入の結果だっけ？」と追いかけないといけませんが、SSAならその手間がなくなりそうだと思いました。

この「値の出所がはっきりする」ことが、コンパイラにとって都合がいいらしい、というところまでが今回の理解です。
その先（具体的にどんな処理が楽になるのか）は、また別の機会に調べたいと思います。

## おわりに

今回わかったのは、ざっくり次のことでした。

- SSAは、コンパイルの途中で使われる「中間表現（IR）」の一種
- ルールは「変数への代入は一度きり」。代入のたびに `x1`、`x2` と名前を振り直す
- そうすると値の出所がはっきりして、コンパイラにとって都合がいいらしい

まだ入り口だけですが、「SSA」という言葉に身構えなくなったのは収穫でした。
