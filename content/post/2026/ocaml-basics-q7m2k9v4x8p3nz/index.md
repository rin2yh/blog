## 演算子や記号の違い

### `%` ではなく `mod`

OCamlでは、整数の剰余は `%` ではなく `mod` を使います。

たとえば、5を2で割った余りを求める場合は次のように書きます。

```ocaml
5 mod 2
```

GoやTypeScriptでは、同じ処理を次のように書きます。

```go
5 % 2
```

GoやTypeScriptでは `%` を使ってきました。C・Java・Python・Ruby・Dartでも `%` を見てきたので、最初は少し違和感がありました。

一方で、以前から `%` では意味が分かりづらいとも思っていました。そのため、`mod` の方がより数学的で分かりやすいと感じました。

### 実数では演算子にも `.` が付く

実数の演算では、次のように演算子にも `.` が付きます。

```ocaml
3.0 +. 5.2
```

整数と実数を厳格に区別するためですが、「毎回小数点代わりにドットを付けることを忘れそう」と思っていました。実際に少し進めたあとも、演算子まで含めて `int` と `float` を区別する癖がありませんでした。そのため、`.` を付け忘れることが多かったです。

### 文字列の連結は `^`

文字列の連結には `^` を使います。

```ocaml
"foo" ^ "bar"
```

冪乗で `^` を使うのかと思っていましたが、浮動小数点数の冪乗では `**` を使います。

この点で驚いてXに書きました。するとhagaさん（@silasolla）から、OCamlでは中置演算子を自作したり既存の演算子を再定義したりできると教えてもらいました。

たとえば次のように定義すると、`^` を冪乗として使うこともできます。（マジすか学園）

```ocaml
let ( ^ ) x y = x ** y
```

### 等値比較は `=`

OCamlの等値比較は `=` です。他言語で慣れた `==` を使ってしまい、文字列の比較で完全にハマりました。（逆に、他の型ではうまくいってしまった）

OCamlでは、文字列の内容を比較する場合も `=` を使います。`==` は物理的等価性を比較する演算子なので、文字列の内容を比較する用途では `=` と使い分ける必要がありました。

これまで触れた言語とOCamlの違いには最初こそ戸惑いましたが、無事理解できました。また、`mod` のようにOCamlの方が分かりやすいと感じる記法もありました。

## イミュータブルな変数

OCamlの変数は基本的にイミュータブルです。一部の型は例外らしく、本の後半で出てくるようです。

Rustも変数がデフォルトでイミュータブルなので、するりと受け入れることができました。関数型のエッセンスを取り込んだ他の言語を扱った経験が生きた形です。

## `let` で関数を書く

OCamlでは、次のように `let` を使って関数を定義します。

```ocaml
let f x = x * 2
```

最初に見たときは「識別子っぽいものが複数並ぶまでは関数かどうか分かりづらい」と感じました。冒頭に `fn` のような関数を示すキーワードがあれば、分かりやすいのになと思いました。しかし、実際に読み書きすると思いの外認知負荷はありませんでした。

一方で、次のような関数の型は最初まったく理解できませんでした。

```ocaml
let f years hours = (jikyu + years * 100) * hours
val f : int -> int -> int
```

ChatGPTと壁打ちしながら、OCamlでは関数が引数を1つずつ受け取る形として扱われることを知りました。もう少し読み進めると、ちゃんと書籍にも書いてありました。ちゃんと読もうね…という自戒です。

`f years` の結果が `hours` を受け取る関数になるため、型も `int -> int -> int` と表現されます。またJavaScriptやTypeScriptで高階関数を使った経験があったため、似たようなものとして少し理解しやすかったです。

## `if` は式として扱われる

OCamlでは、`if` は式として扱われます。次のように書きます。

```ocaml
if 条件 then 式 else 式
```

`then` と `else` の後には式を書き、両方の式は同じ型である必要があります。`if` 全体も式なので、その結果を別の式の一部として利用できます。

普段よく使うGoやTypeScriptでは、`if` は文として扱われます。条件分岐の結果を値として直接利用できず、必要な場合は変数への代入などを分岐の中で行います。そのため、`if` の結果を値として扱える点には少し驚きました。一方でRustでも `if` は式として扱われます。そのため、若干馴染みがありました。

## パターンマッチ・組・レコード

OCamlでは、`match` を使ってパターンマッチを書くことができます。

```ocaml
match x with
| 0 -> "zero"
| _ -> "other"
```

パターンマッチは少し独特な気もしましたが、思いの外慣れてしまいました…。過去にTSKaigi 2026のアフターパーティーで[登壇した際](https://www.docswell.com/s/rin2yh/Z4N4NW-rethinking-neverthrow-is-not-for-me)は、TSらしくないと判断したほど馴染まないと思っていたのですが…！

また、組やレコードも特に違和感なく馴染みました。PythonやRustでタプルを使ったことがあり、TypeScriptではオブジェクト型や `Record` 型が存在します。そのため、すでに知っているデータ構造と対応させながら理解できました。

これまでにも他の言語を学ぶ際にリンクする感覚があり、今回も過去に言語を学んだ経験が役に立ちました。AI時代では詳細を知らなくても良いと言われます。一方で関数型プログラミングを学ぶ上では、学んでおいて損はありません。

## リスト

9章ではリストが出てきました。OCamlでは、リストの先頭に要素を追加するときに `::` を使います。

```ocaml
1 :: [2; 3]
```

このセミコロン2つ `::` はconsと呼ばれます。consはconstructに由来します。クラスを使う際によく見かけるconstructorは知っていましたが、consという言葉はこれまで聞いたことがありませんでした。

また、リストは他の言語同様の表現も可能です。

```ocaml
[1; 2; 3]
```

フォーマッタによって、先ほどのconsを使う形から自動で整形されることもあります（この方が好き）。

さらに、`::` はパターンマッチでも使います。

```ocaml
match lst with
| [] -> ...
| first :: rest -> ...
```

式の中ではリストを組み立てるために使いますが、パターンの中では先頭要素と残りのリストに分解します。この違いは最初に見たとき、「同じ `::` なのに役割が変わるのか」と一瞬理解できませんでした。この仕組みについては未だに理解できていないので、別途調査・学習予定です。

細かい話ですが、リストのパターンマッチで網羅できていない場合にLSP側から警告を出してくれる点も地味にありがたかったです。

## 再帰関数

OCamlでは、再帰関数を `let rec` で定義します。

```ocaml
let rec f x =
  ...
```

再帰関数を書くことは久しぶりだったので、最初は感覚を忘れていました。しかし、大学の講義で学習した感覚は意外と残っていました。演習を2回くらいやると思い出してきました。

一方で、C言語では `rec` を記載せずに再帰関数を実装できます。そのため、OCamlでは何度も `rec` を書き忘れました。書き忘れた場合はLSPから指摘されるので、指摘を見てから `rec` を付けました。（LSPありがとう…）

## 局所変数定義

10章では、次のような局所変数定義が出てきました。

```ocaml
let 変数名 = 式1 in 式2
```

意味自体は理解できましたが、他の言語で見かけなかったので独特な書き方に感じました。その一方で、変数のスコープを `in` で明示する点は分かりやすいような気もしました。（すごくどうでも良いですが、難読クイズにできそうだなとも思いました）

しかし次のように再帰関数の計算結果を一度保持する用途では、読みづらさを感じませんでした。

```ocaml
let rec gakusei_max lst =
  match lst with
  | [] -> { namae = ""; tensuu = min_int; seiseki = "" }
  | first :: rest ->
      let max_rest = gakusei_max rest in
      if first.tensuu >= max_rest.tensuu then first else max_rest
```

また、変数名の部分にはパターンを書くこともできます。この点は「めっちゃ便利」だと感じました。

これまではパターンマッチを使う機会が多く、値を分解するときは先に `match` を書く癖を付けました。そのため、局所変数定義を学んだ直後は使う場面に気付かないこともありました。しかし何度か使う内に、「ここは局所変数定義を使うことができそう」と気付けるようになってきました。11章に入る頃には「意外と局所変数定義を使えてる」という感覚になりました。少しずつ慣れてきた感じがあります。

## 再帰関数の適切な使い方を理解できた

『プログラミングの基礎』では、繰り返しの処理をループではなく再帰関数で書いていました。OCamlにも `for` 文はありますが、パターンマッチと再帰関数を使って繰り返しを表現しています。

大学の講義で再帰関数を学んだときは、まだプログラミング初心者でした。当時は再帰関数を使いこなすイメージを持つことができず、少し玄人向けの書き方という印象がありました。一方で本書では、同じ処理を繰り返し適用しながら処理対象を小さくします。そのため再帰関数そのものより、適切な使い方を理解できたことが今回の学習では大きかったです。
